## Export inventory

Loaded local and recovered macOS arm64 `.node` files separately with Node. Both expose `MicrophoneCapture`, `StealthKeyboardTap`, `SystemAudioCapture`, `applyStealthToWindow`, `calendarAuthorizationStatus`, `deactivateDodoKey`, `getCalendarEvents`, `getDefaultInputDeviceId`, `getDefaultOutputDeviceId`, `getHardwareId`, `getInputDevices`, `getMicUsers`, `getOutputDevices`, `getSystemAudioRecordingPermission`, `getVisibleWindows`, `inputInUse`, `isAccessibilityGranted`, `probeOutputRoutes`, `readCallTree`, `requestCalendarAccess`, `screenCaptureDisplaysAvailable`, `setForeignWindowsCaptureExcluded`, `validateDodoKey`, `verifyDodoKey`, and `verifyGumroadKey`. Only the recovered binary exposes `takeNativeCaptureLog`. The three class prototype method lists are equal. The recovered app contains macOS arm64 and x64 binaries; local checkout contains only an arm64 binary. No recovered Windows binary was present, so Windows export parity remains unsure.

## Cross-platform and packaging limits

Local source explicitly splits system audio (`speaker/macos.rs` and `speaker/windows.rs`) and keyboard hooks (`keyboard_tap.rs` and `keyboard_hook_windows.rs`). The recovered package's macOS binary cannot establish Windows behavior. The compiled app manifest preserves dependency versions but strips Electron Builder configuration, so `asarUnpack`, extra resources, signing and targets cannot be verified against the recovered build. Neither platform was physically exercised here. No code or binary was changed.
